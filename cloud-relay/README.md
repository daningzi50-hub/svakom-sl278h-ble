# Svakom SL278H 云端远程控制（无需蓝牙桥）

用官方 App 的「远程房间」当通道，从任意一台服务器控制 SL278H。
**不需要电脑靠近设备，不需要 Web Bluetooth，不需要浏览器一直开着。**

本目录与仓库根部的 BLE 方案并存，互不替代，按场景选一种即可。

---

## 一、跟 BLE 方案的区别

仓库根部的 `bridge/` + `relay/` 是**蓝牙直连**方案：
浏览器用 Web Bluetooth 连上设备，服务器把指令转发给浏览器，浏览器再写入 BLE 特征值。

| | BLE 方案（`bridge/`） | 云端方案（本目录） |
|---|---|---|
| 需要一台电脑在设备旁边 | **需要** | 不需要 |
| 需要浏览器页面一直开着 | **需要** | 不需要 |
| 控制端与设备的距离 | 蓝牙范围内（约 10 米） | **任意距离** |
| 设备侧要做什么 | 连上浏览器 | 用 App 建一个远程房间，报出房间号 |
| 依赖官方服务器 | 否 | **是**（`ws://47.92.204.177:9092`） |
| 协议层级 | BLE 特征值（`55 04 ...`） | 云端文本指令（`85-3-0-0-2-6-0`） |

一句话：**BLE 方案更独立，云端方案更自由。** 人不在同一个房间时，只有后者可用。

---

## 二、准备

```bash
pip install websockets
python3 server_ws.py          # 监听 :18099
```

设备侧（手机 App）：

1. App 用蓝牙连上 SL278H
2. 进入「远程模式」，创建房间
3. 把界面顶部的**房间 ID**（9 位数字）交给控制端

房间会失效。失效后让持有设备的一方重开一个即可。

---

## 三、最短可用流程

```bash
# 1. 加入房间
curl -X POST localhost:18099/toy-join \
     -H 'Content-Type: application/json' \
     -d '{"room_id":"123456789"}'

# 2. 振动：2 号模式，强度 6，持续 8 秒后自动停
curl -X POST localhost:18099/toy-cmd \
     -H 'Content-Type: application/json' \
     -d '{"mode":"vibrate","pattern":2,"intensity":6,"duration_ms":8000}'

# 3. 开加热
curl -X POST localhost:18099/toy-heat \
     -H 'Content-Type: application/json' -d '{"on":true}'

# 4. 全停
curl -X POST localhost:18099/toy-stop -d '{}'
```

## 四、指令格式

云端指令是一条短横线分隔的字符串，七段：

```
85-{功能}-{加热开关}-{加热温度}-{模式}-{强度}-0
```

| 段 | 含义 | 取值 |
|---|---|---|
| 1 | 固定前缀 | 恒为 `85` |
| 2 | 功能位 | `3`=振动 `5`=加热(主机) `7`=拍打 `8`=伸缩 |
| 3 | 加热开关 | `1`=开 `0`=关 |
| 4 | 加热温度 | 开启时为 `55`，否则 `0` |
| 5 | 模式 | 见下表，`0`=停 |
| 6 | 强度 | **仅振动有效**，其余功能必须为 `0` |
| 7 | 保留位 | 恒为 `0` |

### 功能与模式范围

| 功能 | 功能位 | 模式数 | 强度 | 加热 |
|---|---|---|---|---|
| 振动 | `3` | 1–10 | 1–8 | 走 `5` |
| 拍打 | `7` | 1–7 | 无（填 0） | 走 `7` 自带 |
| 伸缩 | `8` | 1–7 | 无（填 0） | 无 |
| 加热（主机） | `5` | `1` | 无 | — |

### 常用报文

```
85-3-0-0-2-6-0      振动 2 号模式，强度 6
85-3-0-0-0-0-0      停止振动
85-7-0-0-1-0-0      拍打 1 号模式
85-7-0-0-0-0-0      拍打器总关（温度与动作一并断开）
85-8-0-0-2-0-0      伸缩 2 号模式
85-5-1-55-1-0-0     主机加热开
85-5-0-0-0-0-0      主机加热关
85-7-1-55-1-0-0     拍打器加热开
```

## 五、三个必须知道的坑

这三条都会让**指令看起来完全成功、设备却毫无反应**，且没有任何报错。

### 1. 温度位会废掉动作指令 ★最容易踩

加热**不是**可以叠加在动作上的标志位，而是**独立的一条 `func=5` 指令**。

```
85-3-0-0-2-6-0      ✅ 振动，温度位是 0-0
85-3-1-55-2-6-0     ❌ 同一条里带温度 → 整条非法 → 被静默丢弃
```

一旦把「当前是否加热」这个状态粘到每一条动作指令上，**开启加热之后所有动作全部失效**。
现象极具迷惑性：接口返回成功，房间里能看到指令，设备就是不动。

**正确做法：温度一条，动作一条，分开发。** 两者互不干扰，可以同时生效（热着动）。

### 2. 强度超范围会被静默丢弃

厂商教程写的 `0-20` 是整条产品线的通用说法。实测单机有效区间约 `5-8`，
填 `12`、`18` 一律无反应——**不是力度变小，是整条指令被丢弃**。
代码里已用 `MAX_STRENGTH = 8` 收敛。

### 3. 房间会把你静默踢出去

服务器会移出长时间不发言的成员。此时 **TCP 仍然连着**，本地状态照样显示「已连接」，
但发出的指令全部被丢弃，表现为「用着用着忽然就不动了」。

`server_ws.py` 已内置保活：每 20 秒重发一次 `1011`（「我在此房间、我是控制端」的声明）。

## 六、HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/toy-join` | `{"room_id":"..."}` 加入房间。房间不存在会**抛错**，不再假装成功 |
| POST | `/toy-cmd` | `{"mode":"vibrate\|pat\|telescope","pattern":N,"intensity":N,"duration_ms":N}` |
| POST | `/toy-heat` | `{"on":true}` 主机加热；加 `{"device":"pat"}` 控制拍打器 |
| POST | `/toy-stop` | 停止动作，默认保留温度；`{"heat":false}` 连温度一起断 |
| POST | `/toy-raw` | `{"content":"85-..."}` 原样发送任意报文。调试协议用 |
| POST | `/toy-listen` | `{"seconds":40}` 监听房间内的报文 |
| GET | `/toy-status` | 连接、房间、设备在线、两路温度状态 |

---

## 七、协议是怎么摸出来的：抄，不要猜

**`/toy-listen` 是本项目最有价值的一个接口。**

云端房间是广播的：房间里任何一端发出的指令，其他成员都能收到。
所以只要开着监听，让持有设备的一方在 App 里手动点几下，
**App 发出的真实报文就会原样躺在输出里**。

```bash
curl -X POST localhost:18099/toy-listen -d '{"seconds":40}'
```

```json
{"code":1003,"content":"85-7-0-0-1-0-0"}
{"code":1003,"content":"85-8-0-0-2-0-0"}
{"code":1003,"content":"85-3-0-0-8-6-0"}
{"code":1003,"content":"85-5-1-55-1-0-0"}
```

上面三个坑，全部是靠这四条报文一次性定位的——
在此之前，靠推理提出过至少五种假设（蓝牙未连、App 需在前台、通道互斥、房间权限、设备故障），**没有一个是对的**。

**遇到设备不动，第一件事永远是开监听，让 App 自己说出正确答案。**

## 八、WebSocket 消息码

| 码 | 含义 |
|---|---|
| 1001 | 创建房间 |
| 1002 | 加入房间 |
| 1003 | 控制指令（`content` 即上文的报文） |
| 1007 | 房间内产品列表变更 |
| 1010 | 设备状态播报，`subConnectState` 是**配件是否真的连上蓝牙** |
| 1011 | 注册身份（保活靠它） |
| 1012 | 离开房间 |
| 1013 | 查询 |

排查时优先看 `1010`：`subConnectState` 为 `false` 说明 App 与设备的蓝牙没连上——
此时房间照建、指令照发、状态照样正常，**唯独设备不会动**。
